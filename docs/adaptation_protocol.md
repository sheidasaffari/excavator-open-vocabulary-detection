# YOLO-World synthetic-positive adaptation pilot — locked protocol

Locked on 2026-10-30 before any adaptation result was inspected.

## Question

Can the fixed 20,000-image Excavision/colored synthetic-positive set improve
YOLO-World's excavator grounding, and which architectural intervention is
responsible: the region–text scoring head, the vision–language fusion neck, or
unrestricted detector fine-tuning?

This is a positive-supervision experiment. It does **not** claim to learn the
excavator/non-excavator boundary because the adaptation set has no hard-negative
machine or isolated-attachment images.

## Fixed data

- Train: the exact `a10/train.txt` list (20,000 unique images; 15,000
  Excavision and 5,000 colored images), unchanged and in its existing order.
- Development/checkpoint selection: MOCS selected set only.
- Never used for training or checkpoint selection: CIS, the frozen web positive
  control, and the corrected frozen confuser set.
- ACID is reported only as an informed secondary result because its box
  distribution influenced construction of the a10 manifest.

The full 20K is intentionally retained. It includes the naturally occurring
visibility/occlusion range present in a10; this pilot does not rebalance or
filter by occlusion.

## Fixed model and text

- Initialization: `yolov8s-worldv2.pt`.
- Text encoder: frozen CLIP ViT-B/32 embeddings generated by Ultralytics.
- Training category text: `excavator`, as specified by the one-class dataset.
- Evaluation prompt: the already locked deployment prompt
  `construction excavator`; `excavator` remains a canonical reference only.

## Intervention arms

All arms use the identical initialization, image list, augmentations, seed and
checkpoint rule.

1. **Score head**: train only WorldDetect's visual embedding projections
   (`model.22.cv3`) and BN contrastive heads (`model.22.cv4`). Freeze the box
   regression branch and the complete backbone/fusion neck.
2. **Fusion + score head**: additionally train the four C2fAttn fusion blocks
   (`model.12`, `15`, `18`, `21`). Keep the box regression branch, ordinary
   backbone and CLIP text embeddings frozen. This is the primary arm.
3. **Full detector control**: train all detector parameters (CLIP text
   embeddings remain fixed because the trainer caches them rather than placing
   CLIP in the optimized model).

## Optimization

- One pilot seed: 0.
- 30 epochs, MOCS validation each epoch, best checkpoint selected only by the
  standard MOCS detection fitness.
- Image size 640, batch 64 per GPU, AdamW, cosine schedule.
- Learning rates: 1e-3 for score-head, 5e-4 for fusion+head, 1e-4 for full.
- Low synthetic-safe augmentation: no mosaic, mixup, copy-paste, auto-augment
  or erasing; mild HSV, scale, translation and horizontal flip only.
- Deterministic mode, AMP enabled, no silent resume or overwrite.

The pilot is intended to identify the right adaptation locus. A later
confirmatory pass must add multiple seeds after one arm is selected on MOCS.

## Outcomes

Primary development outcomes: MOCS AP50 and AP50:95.

After the checkpoints and selection are frozen, report:

- CIS and frozen web positive-control AP50/AP50:95 plus fixed operating-point
  precision/recall/F1;
- corrected frozen confuser firing/image and predictions/image;
- ACID as an explicitly informed secondary result;
- an open-vocabulary retention check on common non-excavator categories.

No threshold or prompt may be reselected from the held-out sets.
